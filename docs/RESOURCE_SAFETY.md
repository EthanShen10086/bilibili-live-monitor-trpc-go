# 资源保护与通知可靠性

2026-10-08：Node、原生 Go、tRPC-Go 共用以下运行规则。当前仍为正常每 1 分钟、本场通知成功后每 5 分钟确认直播状态；30 分钟尚未启用。没有改变系统休眠、电池、散热或电源设置。

## 等待本次开机确认

未确认或选择“暂不启用”时，状态变化立即写入，稳定状态每 10 秒保活；不再每秒重写文件。确认对话框打开期间也保持 10 秒状态保活。外部 `confirm-start` 通常在约 10 秒内被等待进程发现。停止信号可提前打断等待。

单实例目录锁仍每 2 秒保活、15 秒判定过期。这是防止多个实例同时发送所需的独立保护，不能仅为了减少唤醒随意延长或删除。

## 网络与内存

Node 流式读取 HTTP 响应，限制读取后的响应体为 2 MiB，检查声明长度并对实际流累计计数。错误状态或超出上限时取消响应体、释放 reader；超时和格式错误继续按现有退避处理，不记录响应正文或凭证。Go 保持 2 MiB 的有界读取，并在成功、失败时关闭响应体。

此上限针对业务 HTTP 响应，不是整个进程的硬内存上限。没有引入频繁杀进程、定时强制重启或手动 GC。官方事件模式仍有自己的帧解析与心跳规则，需要平台授权后单独验收。

## 日志

`events.log`、`service.log`、`error.log` 分别限制为 2 MiB，各保留最多 3 个备份。应用可见的三组日志通常合计不超过约 24 MiB；系统日志、临时文件和运行时仍持有的旧文件描述符另计。

Node 在 managed 入口捕获标准输出和错误输出；Go 在 managed 主程序重定向描述符，因此框架在初始化时缓存的标准输出也能被捕获。退出前 Go 恢复描述符并排空日志管道。正常手动命令继续输出到终端。单个超长写入最多保留末尾 64 KiB；超长日志可能截断，应以数据库和状态文件作为业务依据。

只有实际输出时才做大小检查和轮转，没有新增每秒扫描日志的后台任务。进入应用管理入口之前的启动失败、操作系统日志由服务管理器负责，应用层不能保证所有系统日志都有上述限制。

## 历史通知记录

```yaml
maintenance:
  history_retention_days: 90
```

省略时默认 90 天，可配置 0–3650；0 关闭自动清理。配置修改后重启生效。

- 每 24 小时最多删除 200 条旧终态记录，按任务过期时间计算保留期。
- 仅清理 sent / failed / expired；pending 任务始终保留。
- 所有 observations 当前引用的场次记录始终保留，因此持续直播、重启后的降频和去重不会因清理而失效。
- 最近一次清理时间保存于 SQLite 的 maintenance 表，迁移和重启继续复用，不因每次重启重复批量删除。
- 使用事务同时完成限量删除和清理时间更新；空闲队列只有记录实际被删除时才刷新统计。
- 不定期 VACUUM，不删除数据库文件。释放的 SQLite 页面可以复用，文件不会必然马上缩小。

超过保留期的非当前场次全局去重记录会被删除；异常重新返回极旧场次时，不保证跨保留期去重。大量导入的旧记录可能需要多天分批清理，避免一次长事务。

## 飞书送达边界

API 成功后才持久化 sent，当前场次才降频。暂时失败继续有限退避，超过任务 TTL 停止补发。普通重启、标题变化和持续直播已覆盖去重测试。

群 Webhook 没有本项目可用的场次幂等键。若飞书已收消息但成功响应丢失，重试仍可能重复；本次保留重试以降低丢消息风险，没有假装提供严格 exactly-once。私聊继续使用稳定 UUID，但真实权限、手机提醒、跨重启与睡眠恢复仍需各自验收。

## 更新与复现

Node 构建后执行 `npm test` 与 `python3 scripts/smoke-node.py`；合集的 smoke-node.py 在仓库根目录，独立 Node 在 scripts/。需要时用 MONITOR_NODE 指定 Node 24 可执行文件。

Go 执行 `go test -race ./...`、`go vet ./...`，按原部署手册构建后执行独立仓库 `python3 scripts/smoke.py` 或合集 `python3 scripts/smoke-go.py`。进程冒烟使用临时目录、假凭证和排除当天的时间窗口，以 managed cloud 的应用逻辑在本机运行，不注册服务、不访问真实云主机、不发送真实通知。

本工作区使用 `outputs/update-resource-safety.command`：检查四个仓库公开清单，重启既有 Mac Node 服务，确认新 PID、resource_safety_version: 1、history_retention_days: 90、正常 60 秒和已通知直播 300 秒，再核对 GitHub 提交。无需重新发送测试消息或修改开机确认决定。

云端沿用 CLOUD.md 的停止、更新构建和 systemd 重启步骤，保留凭证与原 SQLite 文件；状态中核验 resource_safety_version: 1 和实际配置。没有真实服务器资源消耗或 SSH 切换的新证明。

资源保护降低可控开销和异常风险，不能保证硬件寿命零影响。Mac 休眠期间无法实时检测；要全天候保障监测，可由云端承担。
